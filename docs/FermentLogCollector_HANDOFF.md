# FermentLogCollector Handoff

FermentLogCollector is a small remote service for collecting glycol event logs
from one or more BrewPi-ESP devices, starting with `TresFermTrack-1`.

The collector must live in its own project/repository, separate from
`brewpi-esp`, so it does not add host-side dependencies to the firmware
workspace.

## Goal

Collect and preserve the ESP glycol event log over long fermentations without
losing data when the ESP rotates its short local log.

The ESP-side log remains the source of truth for controller events. The remote
collector periodically fetches completed log archives and appends them into a
long-term CSV.

## Device Contract

Expected ESP endpoints:

- `GET /glycol_log.csv`
  - Current log segment.
  - The ESP may still be writing to this file.
  - Used for live inspection only.

- `GET /glycol_log.archived.csv`
  - Most recent completed log segment.
  - The ESP no longer writes to this file.
  - This is the primary input for durable collection.

The archived endpoint may return `404` before the first ESP-side rotation. That
is not an error condition.

## Glycol CSV Format

The CSV header currently generated by BrewPi-ESP is:

```csv
timestamp,millis,from_state,to_state,current_temp,setpoint,cooling_rate,cooling_duration_s,coast_estimate,learned_k,learned_C_off,learned_L,force_minimum,reason
```

The combined collector CSV must contain this header once, followed by data rows
from each newly acquired archive. When appending an archive, skip the archive's
header row.

## Collector Behavior

For each configured device:

1. Poll `{base_url}/glycol_log.archived.csv`.
2. If the response is `404`, record that no archived log exists yet.
3. If the response is successful:
   - compute SHA-256 of the file content;
   - compare it to hashes already collected for that device;
   - if already seen, do not append;
   - if new, save the raw archive and append its data rows to the combined CSV.
4. Optionally poll `{base_url}/glycol_log.csv` and save it as a live snapshot.
   Do not append the current live file to the durable combined CSV.

Hash-based de-duplication is required. The simplest first version may track only
the most recent archived hash, but storing all seen archive hashes is safer.

## Collector Audit Log

The collector must keep a human-readable text log, rotated monthly:

```text
logs/collector/collector-YYYY-MM.log
```

Example lines:

```text
2026-08-08T13:01:00+02:00 INFO TresFermTrack-1 archived log unchanged hash=a8f3... bytes=42155 rows=180 duration_ms=184
2026-08-08T13:02:00+02:00 WARN TresFermTrack-1 archived log not found status=404 duration_ms=91
2026-08-08T13:03:00+02:00 ERROR TresFermTrack-1 fetch failed error=timeout duration_ms=5000
2026-08-08T13:04:00+02:00 INFO TresFermTrack-1 new archived log appended hash=b712... rows_appended=211 bytes=49320 duration_ms=240
```

The audit log should answer:

- when the collector attempted a fetch;
- whether the device was reachable;
- whether the archived file existed;
- whether the file was new or already seen;
- how many rows were appended;
- what hash was recorded;
- how long the operation took.

## Web GUI Requirements

Initial screens:

- Device list
  - name;
  - base URL;
  - enabled/disabled;
  - last attempt;
  - last success;
  - last new archive;
  - current status;
  - consecutive failures;
  - rows collected.

- Device detail
  - edit name and base URL;
  - edit polling interval;
  - enable/disable collection;
  - fetch now;
  - show recent collector audit lines;
  - download combined CSV;
  - download latest raw archive;
  - download latest live snapshot.

The first configured device should be:

```text
Name: TresFermTrack-1
Slug: tresfermtrack-1
Base URL: user-provided
Polling interval: 60 seconds
Enabled: false by default until configured
```

## Suggested Stack

Recommended simple stack:

- Python 3
- FastAPI
- SQLite
- Jinja2 or HTMX for the web UI
- `httpx` for HTTP polling
- standard `logging` module for monthly text logs

Avoid adding this service to the `brewpi-esp` firmware repository.

## Compatibility With Current Firmware

Current firmware likely exposes:

- `GET /glycol_log.csv`

Current firmware does not yet expose:

- `GET /glycol_log.archived.csv`

The collector should handle this gracefully by showing:

```text
Archived log not supported or not present yet.
```

After the ESP-side archived-log rotation is implemented, the collector should
start acquiring durable archives automatically.
